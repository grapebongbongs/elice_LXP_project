# 현재 튜터 + 반복 제출 평균 최고 가드

## 선택 근거

보관된 공식 제출 기록에서 동일 가드 구현으로 확인되는 반복 관측을 비교했다.
로컬 점수와 공식 점수, 단일 최고점과 반복 평균은 섞지 않았다.

| 공식 제출 그룹 | 확인한 가드 점수 | 횟수 | 평균 |
|---|---|---:|---:|
| b4dd478 / 0446be2의 동일 가드 | 93.69, 94.63 | 2 | **94.16** |
| 277d1fe 동일 커밋 | 91.76, 95.94, 92.84, 93.05, 92.16, 90.54, 92.41 | 7 | 92.67 |
| cd62904 | 93.24, 88.96, 93.43, 92.40 | 4 | 92.01 |

근거는 log_64_84.md의 #82 공식 제출(93.69), log_84_104.md의 #85 공식 제출
(94.63) 및 277d1fe 반복 제출, log_24_44.md의 과거 제출이다.
`git diff b4dd478 0446be2 -- baseline/app/guard baseline/app/common baseline/app/config.py`
결과가 비어 있어 두 커밋의 가드와 공통 의존성이 동일함을 확인했다.
0446be2의 94.63 한 번만 평균 최고로 간주한 것이 아니다.
관측 2회뿐이므로 안정적인 94점이나 통계적으로 더 좋은 구현임을 보장하지 않는다.

## 결합 방식

- 튜터: 직전 제출 bb32e5b의 팀 참조 튜터 유지.
- 가드: 0446be2의 전용 pipeline/config/policy/prompts를 적용.
  입력 자료는 검색 1개, 입력 medium/출력 low, 출력 검증은 1회다.
- 과거 가드의 LLM 래퍼를 `baseline/app/guard/llm.py`로 분리해 유지했다.
  현재 튜터의 공통 래퍼로 호출하면 tag 인자와 보조 호출 동작이 달라지기 때문이다.
- 가드 래퍼는 튜터와 동일 세마포어를 공유한다. 별도 래퍼 때문에 전체 동시성 상한이
  두 배가 되지 않는다. 로그는 기존 시간·상태·오류 메타데이터만 남긴다.
- 공통 KB/normalize/schema는 두 버전 간 Git diff가 없어 공유했다.
- 튜터 파일의 SHA-256 보존 및 튜터가 가져오는 가드 프롬프트 상수 동일성도 확인했다.

## 검증과 상태

`python -u -m unittest discover -s baseline/tests -v` — **21개 통과**.
인증된 mock 동시 요청 64개, 잘못된 토큰 401, 가드 검색 자료 1개, 출력 호출 1회,
기존 transport의 비헤지 호출, 원문 구간 복원, 튜터 기능 및 프롬프트 호환성을 검증했다.
첫 실행에서 검색 개수 k를 무시하던 테스트 대역이 발견되어 실제 검색 인터페이스에
맞게 수정한 뒤 전부 통과했다. 제품 코드를 테스트에 맞춰 바꾸지는 않았다.

외부 LLM 호출·실제 공개 세트 채점·배포·공식 제출은 하지 않았다.
94.16은 과거 가드의 관측 평균이며 이 결합본의 실측 점수가 아니다.
현재 마지막으로 확인한 공식 제출 기록은 bb32e5b / 89.88이다.
